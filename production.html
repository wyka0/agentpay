SECTION: LIFECYCLE
004
01

REQUEST

Agent requests a service by selecting from the available registry and providing required input parameters.

02

POLICY

Server evaluates the request against the agent's spending policy using trusted accounting from the verified ledger.

03

INTENT

AgentPay creates an immutable payment intent with fixed amount, recipient, chain, and expiry. Values cannot be modified.

Agent receives the structured service result. The result is bound to the request, payment, and trusted ledger entry.

SECTION: SECURITY_MODEL
010

TRUST IS
VERIFIED.

Every layer of AgentPay is designed so that trust never assumes — it verifies.

SERVER POLICY

Policy evaluation occurs against trusted server-side accounting. The browser never decides what an agent can spend.

IMMUTABLE INTENTS

Approved payment values cannot be modified by the agent, the user, or any client-side logic. The intent is fixed at creation.

ON-CHAIN VERIFICATION

Transaction facts are independently verified on Arc. The server checks amount, recipient, sender, and token against the intent.

EXPLICIT SIGNING

Wallet authorization remains an explicit user boundary. No autonomous signing. No custodial keys. The user confirms every transaction.

TRUSTED LEDGER

Verified payments become the accounting authority. Browser storage is never the source of truth for spending limits.

SERVICE GATING

Service fulfillment requires verified payment. The service adapter only executes after the trusted ledger confirms payment.
